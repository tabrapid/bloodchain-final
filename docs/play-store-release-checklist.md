# Google Play release checklist — Bloodchain donor app

What the repository already provides, what the operator must supply, and the
exact commands. One row per item; "repo" means it is in this branch and
verified by CI, "operator" means an account, key, hostname or decision that
cannot live in a repository.

## 2. What the operator must supply

| Item | Why | Where it goes |
| --- | --- | --- |
| Production API hostname (https, public) | the build refuses without it | `EXPO_PUBLIC_API_URL` in the EAS `production` profile's env or an EAS secret |
| Published privacy policy URL (uz/ru/en) | Play listing requirement; the app links to it | `EXPO_PUBLIC_PRIVACY_POLICY_URL`. Draft: `docs/legal/privacy-policy.md` (needs legal review and the three `[...]` fields) |
| Published terms URL | app links to it | `EXPO_PUBLIC_TERMS_URL`. Draft: `docs/legal/terms-of-service.md` |
| Account-deletion web URL | Play requires a web page where a user can request deletion without the app | a page on the same site as the policy, describing that deletion is in the app under Privacy and giving the contact address |
| Expo account + EAS project | builds and push notifications | `eas init` writes `extra.eas.projectId`; or `EXPO_PUBLIC_EAS_PROJECT_ID` |
| Android upload keystore | signing | `eas credentials` (EAS-managed) or a local keystore |
| Google Maps Android key | SOS journey and courier maps on Android | `GOOGLE_MAPS_ANDROID_API_KEY` as an EAS secret |
| Google Play developer account, app listing, screenshots (the capture set in `artifacts/mobile-v4-visual-qa/` is browser-rendered; take real device screenshots for the listing) | | Play Console |
| Legal decision: retention period and basis for the donation record after deletion | the deletion screen and the policy name the records but not the period | fill in `docs/legal/privacy-policy.md` |

## 3. Build and submit

```bash
# once
npm i -g eas-cli
eas login
cd apps/mobile && eas init            # writes extra.eas.projectId into app.json; commit it

# secrets (never commit these)
eas secret:create --scope project --name EXPO_PUBLIC_API_URL --value https://api.<your-domain>
eas secret:create --scope project --name EXPO_PUBLIC_PRIVACY_POLICY_URL --value https://<site>/privacy
eas secret:create --scope project --name EXPO_PUBLIC_TERMS_URL --value https://<site>/terms
eas secret:create --scope project --name GOOGLE_MAPS_ANDROID_API_KEY --value <key>

# the store build (app-bundle, APP_ENV=production, signed with EAS-managed credentials)
eas build --platform android --profile production

# submit to the internal testing track first
eas submit --platform android --latest
```

Before each upload raise `android.versionCode` in `app.json` by one and commit;
`eas.json` uses `appVersionSource: local`, so the number comes from the file.

## 4. Play Console — Data safety form (answers from the code)

| Question | Answer |
| --- | --- |
| Does the app collect or share user data? | Collects: yes. Shares with third parties: no (hospital / blood-centre staff are the service's own users; Google Maps tiles on Android are a platform service) |
| Encrypted in transit | Yes (TLS; cleartext refused in production builds) |
| Users can request deletion | Yes — in-app (Privacy → Delete account) and via the web URL above |
| Personal info: name, email, phone | Collected, required for app functionality (account) |
| Health info: blood group, donation and laboratory records | Collected, required for app functionality; not shared with third parties |
| Location: approximate (home area), precise (during an emergency journey or a delivery, user-initiated) | Collected, optional, app functionality |
| Device or other IDs: push token | Collected, optional, app functionality (notifications) |
| App activity: in-app actions (appointments, responses, recognition) | Collected, app functionality |
| Financial, contacts, photos, messages, files, calendar, audio | Not collected |
| Advertising / analytics SDKs | None |

Content rating: no user-generated content beyond a moderated community feed;
medical content present (informational). Target audience: adults (18+).

## 5. Before the first public release

- Run the native capture on a device (`apps/mobile/qa/visual/run-native-capture.sh android`) and keep the screenshots: everything in `artifacts/` is browser-rendered.
- Confirm push notifications arrive on a release build (needs the EAS project id).
- Confirm a map draws on Android (needs the Maps key).
- Publish the three legal pages in uz, ru and en, then set the two URLs and rebuild.
